## Per-90 review — the next session's focus

**Where it lives** (the whole surface — it is small):
- `backend/app/stats.py:173-177` — the computation
- `backend/app/schemas.py:47` — `per_90: float | None` (players only)
- `frontend/src/api.ts:63`, `pages/EntityView.tsx:409`, `pages/PlayerView.tsx:288`

**The computation today:**
```python
minutes_total = sum(r.minutes for r in rows if r.minutes is not None)
per_appearance = (total / games) if games else None
per_90 = (total / minutes_total * 90) if minutes_total else None
```
where `total` sums only non-NULL metric values, and `games = len(rows)`.

**Measured on the live DB (317,902 player_match rows), not assumed:**

| condition | rows | effect |
|---|---|---|
| `minutes` NULL, `shots` present | **0** | the inflation risk does NOT exist |
| `minutes` present, `shots` NULL | **41,825 (13%)** | see below |
| `minutes = 0` | 0 | the "appearance = minutes > 0" rule is currently inert |
| `minutes` NULL | 0 | denominator is always complete |

**The question to answer:** `average` divides by `len(values)` (non-NULL metric
rows only) while `per_90` divides by `minutes_total` (ALL rows, including the
41,825 where the metric was never recorded). So the two headline numbers use
**different denominators**, and `per_90` is systematically deflated for any
metric absent from a match page — CLAUDE.md's documented "payload varies per
match" quirk (`Min`/`Gls`/cards present, `Sh`/`SoT`/`TklW`/`Fls` NULL).

Whether that is wrong depends on intent, which is why this is a REVIEW and not a
bug report: minutes played with no shot recorded may legitimately belong in the
denominator, or may be missing data that should be excluded. **Decide the
contract first, then change code.** A known-output regression test is the
project rule for statistical code.

**Also in scope for the review ("infrastructure"):** `per_90` is computed in the
API request path per call rather than stored (consistent with the
"don't store rolling features" convention — confirm that still holds at L1/L2
volume); it is players-only; and `hit_rate` thresholds run on RAW per-match
values, never per-90, so a "per 90" threshold filter does not exist.

## Standing gotchas (this session's additions in bold)
- **Read the digest with dates in mind — it reports history, not just live faults.**
- **A background `nohup ... &` returns immediately; the "task completed"
  notification is the WRAPPER, not the job. Wait on a log marker instead.**
- **Wall-clock moves slower than it feels — check `date` before concluding a run
  has stalled. I twice mistook a healthy run for a hang.**
- `&&` is a parse error in PowerShell 5.1.
- Git Bash mangles `cmd //c run_x.cmd` — use `& cmd.exe /c "<abs path>"`.
- `pytest` piped to `tail` hangs — redirect to a file.
- `uvicorn --reload` and Vite HMR are unreliable under OneDrive.
- **Repo-wide `grep` over the tree is slow enough to time out — use the Grep tool.**
- MCP `postgres` points at the wrong DB — query via `backend/.venv` +
  `SessionLocal()`. (This session it failed to connect at all.)
- **`.gitignore` covers `*.log` but not `*.txt` — generated reports need adding.**
