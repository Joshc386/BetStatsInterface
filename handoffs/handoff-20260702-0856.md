## Key non-obvious facts learned (saved to memory — read them, don't re-derive)
- **Two-spelling seam** (why the alias churn happened): `cups.py` resolves fixture teams from the FBref *schedule/caption* name, but `ingest_match` re-resolves each player's team from the *player-df* name (name-only, fail-loud). When they differ (`Peterborough`↔`Peterborough United`, `MK Dons`↔`Milton Keynes Dons`) it dropped the tie. Fixed with deterministic `FBREF_TEAM_ALIASES` entries (both spellings). Alias set has **converged** — EFL Cup 2425/2526 ran first-pass clean. Full club list is in the "Domestic-cup … draw" comment blocks in `ingestion/players.py`. → `memory/cups-internationals-sourcing.md`.
- **Scorebox parse gotcha:** a 10+ score uses `class="score double"`; `parse_scoreline` matches the `score` class *token* (not exact `class="score"`), else double-digit results are dropped (Man City 10-1 Exeter). Regression-tested.
- **cup `team_match` is DERIVED from the same FBref data as player rows**, so shot/foul totals can't cross-validate the player data (equal by construction). Only the scorebox `gf`/`ga` is independent — that's what makes the standing `sum(player goals) ≤ gf` invariant meaningful on cup rows now.
- Live-FBref discipline still applies for any future cup/Euro fetch: **VPN off, headful, under the watchdog** (`ingestion/run_backfill.py`); one-shot cup fetches hang on Cloudflare. → `memory/player-data-fbref-blocked.md`.
