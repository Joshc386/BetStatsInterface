### 1. Nightly automation — now live
- Windows Task Scheduler has three real jobs (confirmed via `Get-ScheduledTask`): **`BetStats nightly`** (07:00, unattended team-data + points refresh), **`BetStats matchday`** (08:00, interactive logon, FBref player-data refresh — deliberately left idle/harmless until real fixtures exist), **`BetStats upcoming fixtures`** (07:30, pre-existing). The old one-off `BetStatsBackfill` task was deleted.
- Both `.cmd` launchers now log failures loudly: a non-zero exit pops a blocking `MessageBox` via `backend/notify_failure.ps1`, so a real failure can't sit silently in a log file unnoticed.
- **A real bug was found and fixed**: `ingestion/points_adjustments.py` reused `upcoming.py`'s `ESPN_LEAGUES` dict, which ADR 0011 had extended with `"World Cup"` for fixture-scoreboard purposes — nations have no points-deduction concept, so ESPN's standings response for `fifa.world` has no `children` key, and the unhandled `KeyError` crashed nightly on every run. Fixed with its own `DOMESTIC_LEAGUES` mapping. Verified live (exit 0, 14 adjustments committed) and via the full test suite.
- Commits: `6b12c00` (points_adjustments fix + matchday wiring), `7fe3752` (nightly failure-notification parity). Both pushed to `origin/master`.
- **Key design point worth remembering**: the FBref/matchday step is genuinely safe to leave running daily even with nothing to ingest — it checks the DB for pending fixtures first and exits in seconds without ever touching FBref if there's nothing pending. No re-enabling needed once the Championship season starts in ~2 weeks.

### 2. Manual QA pass — one real bug found and fixed, rest is clean
Ran the actual dev servers (`api` + `frontend` from `.claude/launch.json`) and drove the UI directly rather than just reading code. Covered: search → player/team stats, threshold/hit-rate filters (numeric + boolean), cross-club segmentation, `min_minutes` filtering, seasons window mode, fixture team-form/H2H/squad-form, and league table + points-deduction history across multiple seasons.

- **Bug found and fixed**: the hit-rate label kept echoing a stale numeric threshold when switching from a numeric metric (e.g. Shots on Target) to a boolean one (e.g. Carded/BTTS) without clearing the threshold field — e.g. "Carded over 1.5" when the `1.5` is meaningless for a boolean metric. The underlying math was always correct; only the label was wrong. Turned out `PlayerView.tsx` and `EntityView.tsx` (team view) are **separate components**, not shared, so both needed the fix independently. Commit `fed030d`, pushed.
- Everything else checked out correct, including some good validation-by-coincidence moments: Saka/Haaland/Gabriel Magalhães season stats matched real-world figures exactly (documented in this conversation, not re-derived here); the league table's points-deduction footnotes reproduce real, well-known cases with exact arithmetic (Derby -21 & Reading -6 in Championship 2021-22 correctly reproducing the actual 3 relegated clubs in order; Everton -8 & Forest -4 in Premier League 2023-24 matching real final positions).
- No other bugs found. This was a genuinely thorough pass — search, both stats engines (team + player), fixture views, and the computed league table are all now manually verified working, not just unit-tested.
