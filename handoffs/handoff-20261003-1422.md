## The Referee hub: what to build

**Domain decisions live in `CONTEXT.md`** (Referee, Appointed referee, Cards,
the Bookings resolution). Do not re-litigate them. In one line each:
- **Unit:** match totals, both sides summed, with the home/away split beneath.
- **Source of cards and fouls:** FBref Player-Match rows in every scope,
  counting every booking. They can differ from the team pages, which follow
  football-data.co.uk's convention; the page must say so.
- **Identity:** the name as the match page prints it, plus a hand-confirmed
  alias list. Never fuzzy-merged; near-duplicates are listed for review.
- **Scope:** captured for every Fixture in every scope. The window defaults to
  League; foreign referees seen only in Europe are labelled "covered ties
  only".
- **Cards:** yellows + reds that did *not* follow a second yellow, so at most 2
  per player. The red rate counts every sending-off.
- **Before kick-off:** an **Appointed referee** picked by hand on the Fixture
  view, held in the URL only (`?ref=<id>`), never stored. Appointments are
  confirmed about a day before kick-off.

**Agreed page (Q8, user: "exactly what I had in mind"):**
- **Reached via:**
  - global search (referees alongside teams and players);
  - the Appointed-referee picker on the Fixture view;
  - the referee named on any played match.
- **Header:** a referee-black theme, reusing `Hero` / `KitShirt` from
  `frontend/src/components/Kit.tsx` with a black kit.
- **Controls:**
  - Metric: Cards / Yellows / Reds / Fouls;
  - Window: last N refereed matches or seasons;
  - Scope: League by default, or Cups / Europe / International / All;
  - Threshold.
- **Headline:**
  - four per-match rates plus a match count;
  - hit-rate on the chosen metric;
  - home-side vs away-side rates beneath.
- **Recent games:** date, home v away with shirts, competition, Cards, Yellows,
  Reds and Fouls. Each match expands into its per-side split.
- **Labels:** FBref-vs-team-page counting; "covered ties only".
- **Explicitly out of v1:**
  - a per-team table on the referee page;
  - a "Referee" filter on team and player pages. This is the agreed follow-up
    slice, cheap once fixtures carry a referee.

**Evidence gathered (not recorded elsewhere):**
- **Referee names:**
  - Cached match pages: `~/soccerdata/data/FBref/match_<fbref_match_id>.html`
    (17,754 of them).
  - Officials line format:
    `<span …>Samuel Barrott (Referee)</span> · … (AR1) · (AR2) · (4th) · (VAR)`.
  - It sits within the first ~100 KB of each page. Reading 140 KB per page made
    a full scan feasible; reading whole pages timed out.
  - All 13,501 league and cup pages are cached; 25 name no referee.
  - **149 distinct names.**
  - Sampled coverage: league 700/700; cups and Europe 94–100%; minor
    internationals ~95%.
- **Alias review list:**
  - Confirmed split: **"Sam Allison" (5) = "Samuel Allison" (171)**.
  - **Investigate "Steve Martin" (96) vs "Stephen Martin" (96).** Identical
    counts are suspicious; the user has not ruled.
  - Different people: Andy vs Robert (Bobby) Madley; Martin vs Ben Atkinson.
- **Before kick-off:** ESPN `summary?event=` `gameInfo.officials` names the
  referee only *after* a match; it was empty for that day's EFL games about
  an hour before kick-off. FBref's cached schedule `referee` column is filled
  for 644/644 played and 0/2,357 unplayed matches.
- **FBref card encoding:** a two-yellow dismissal is `yellows=2, reds=1` in
  715/715 league rows. `second_yellows` is NULL in every row (not in `summary`).
  Derive it: a red on a row with yellows ≥ 2.
- **Source disagreement:** football-data.co.uk vs FBref yellows disagree on
  3.6% of league team-sides; 88% of those had a red.

**Build plan to propose (needs the user's approval; the schema change needs an
explicit plan, approval and a dry run per CLAUDE.md):**
1. **Migration:** a `referees` table (canonical name) and
   `fixtures.referee_id` (nullable), plus an alias map in code. Run Alembic
   `--sql` first as the dry run.
2. **Zero-network backfill from the cached pages**, with the near-duplicate
   review gate printed for the user (as with the player data-quality gates).
   Idempotent.
3. **In-season capture at FBref ingest.** `ingestion/players.py` already parses
   the scorebox (~line 557, `ingest_match` ~465); the officials line is in the
   same block. Check that the cup/European/international paths, which go
   through `fbref_shim` / `cups`, reach it too.
4. **API:** referee search, `GET /referees/{id}/summary`. Cards are computed at
   query time from `player_match`; nothing derived is stored (CLAUDE.md
   data-model rules).
5. **UI:** the referee page, the search entry, the Fixture-view picker
   (`?ref=`), and the referee shown on played matches.

**ADR candidate (not yet offered to the user):** "Referee figures come from
FBref player rows, not team rows". It is surprising without context and the
result of a real trade-off. Offer it when building.

## The Matchup view: grill first
- **Agreed so far:** only that it's wanted. It shows one side's "for" beside the
  other side's "against" on the Fixture view (e.g. home corners won vs away
  corners conceded).
- **Fact:** every `team_match` row pairs with its opponent's row (0 of 34,882
  unpaired), so "against" figures come from a self-join with **no ingestion
  change**. `FixtureRow` / `GET /fixtures/compare` currently carry
  `shots_conceded` / `sot_conceded` but not corners/fouls/cards against.
- **Questions to grill:**
  - Which metric pairs (corners, shots/SoT, fouls committed vs suffered, cards,
    goals)?
  - Which windows and venue? The existing home/away venue toggles probably
    apply.
  - Where it sits: a new View mode, or inside Team form?
  - Any "combined" figure? It must not read as a prediction; the project is
    "not a predictive model".
